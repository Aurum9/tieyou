# 牌库 · EDH ATELIER

面向中文玩家的万智牌卡查、EDH 组牌及手动测试工作台，当前为 V0.3.0 试用版。

## 运行

使用 Node.js 22.13+，安装后启动本地网页与检索服务。

```text
npm ci
npm start
```

打开终端给出的地址，默认 http://127.0.0.1:4173/。

首次启动会将 `web/data/` 冻结数据建立为本地 SQLite 索引，后续启动复用 `.local/catalog.sqlite`。网页通过 `/api/catalog` 分页检索；卡组按身份与已选版本读取，详情和其余印刷版本按需读取。卡图在线访问 Scryfall，用户卡组继续保存在当前浏览器。

`npm run build` 生成 `dist/server/index.js` Worker 及 D1 迁移文件。Sites 使用 `.openai/hosting.json` 中的现有项目和 `DB` 绑定部署；部署包不含全量 JSON 分片。完整卡库通过独立维护脚本分批导入，数量与索引校验通过后才切换启用版本。原始卡库只作为服务端种子与离线验证资料保留在源码中。

## 已实现

- 手机布局：44px 触摸按钮、16px 输入与选版、全屏筛选及底部“查看结果”、窄屏组牌与导入导出、安全区域适配。
- 精简页面说明、口号与无问题检查提示；组牌检查只显示已发现的具体问题，译文来源收进详情折叠项。
- 默认首页为卡组库，只读取浏览器本地记录；打开编辑器只请求该套牌用到的身份与版本，导入牌表由服务端匹配相关卡牌。
- 独立卡查入口继续保留。空搜索不请求卡牌；有效查询由服务端检索，每次返回 48 张摘要，点击继续加载才取下一页。清空查询和筛选后恢复空白搜索页。
- 中英文名称、规则文字搜索；简略／高级筛选切换，隐藏后仍生效的高级条件以角标、保留提示和可移除标签展示。
- 基础卡牌颜色与高级标识色独立筛选，均支持任一、全部、恰好、仅在所选范围内四种关系；法术力值提供含边界的上下限，留空不限，支持 0 和小数。
- 高级模式提供真实 Scryfall 功能标签，支持任一／全部关系与完整词表输入建议；系列代码及名称也提供输入建议。
- 可视化编辑所有支持字段及 AND／OR／NOT、嵌套条件组，文字自动安全转义；主搜索框保留手写高级语法。
- 高级筛选直接提供超类别、副类别、力量／防御力上下限；副类别有中英文建议，数值支持负数和小数，多面牌的类型和身材条件在同一面匹配。
- 卡牌筛选、主将标识色限制及非默认排序实时显示在搜索框；默认 EDH 合法性与名称排序保留在可见控件中，不自动写入框。手写条件与勾选的合法性共同生效。修改手写部分可以保留完整生成片段，重写生成片段后保留当前合法性勾选，随后继续点选可添加条件。
- 从卡组编辑器以空牌名进入高级搜索时，主将标识色本身就会触发搜索，直接展示范围内卡牌；无目标的默认空卡查继续保持空白且不下载卡库。
- 支持 EDHREC 热度顺序，使用当前 Scryfall 冻结快照的真实排名，缺失排名置后。卡查显示当前目标卡组中的主牌／统帅／候选数量，未选目标时显示包含该牌的卡组数。
- 多牌面详情、中英对照与印刷版本选择；系列、编号、稀有度和语言按同一印刷版本组合匹配。
- 卡组新建、编辑、复制、删除恢复，统帅／主牌／候选牌分区、数量、选版、分类和备注。
- 卡组编辑器输入后实时显示前 8 个卡片候选，直接加入当前主牌区；已移除查找按钮与原生名称下拉，更多结果可通过高级搜索查看，添加后保留搜索内容。
- 编辑器的高级搜索携带当前卡组、搜索词及主将标识色限制，跳转后展开高级筛选。卡查加牌直接写入该卡组主牌区，返回后保留编辑器；编辑器内详情加牌也使用当前编辑卡组。
- 独立卡查上方提供目标卡组开关及选择栏；选定后各加牌入口直接加入目标主牌区，未选择或清除选择后，点击加入显示原有卡组／分区选择窗口。
- 卡名、系列编号、搜索结果三种加牌入口；卡组内搜索默认按已选主将的标识色并集限制，包含无色，并可手动取消限制。无色主将仅显示无色标识牌，无主将时不限。
- 文本导入的逐行检查、歧义修正与明确跳过，文本及完整 JSON 导出。
- JSON 原子新增恢复，浏览器保存失败提示与损坏存储保护。
- 调度阶段手牌优先、横向排列并可滚动，只保留调度次数、沉底进度与按钮；设置保留起手张数、生命、免费调度次数及先手抓牌。
- 正式试牌同时显示上方战场、下方手牌；坟场、放逐与统帅区采用手牌旁边的卡片堆。所有区域可拖拽移动；展开的牌库和牌堆也可拖回桌面。
- 战场点牌直接横置／重置；角落菜单、长按或右键进入操作。菜单提供计数器增减、双面牌转化、倒转牌倒转、详情及键盘可用的移动入口。
- 下地无次数限制，后续回合固定重置和抓牌。页面移除撤销／重做及规则说明段落；旧存档继续兼容。
- 每套卡组独立保存测试进度，刷新后可续测；保存失败明确提示，损坏进度可下载原始内容，覆盖前需明确选择。测试不写入原卡组。

## 验证与数据

当前 JavaScript 检查覆盖 SQL 与原查询差分、分页与按需读取、组牌、试牌、拖拽、旧存档及导入失败保护；10 项 Python 冻结数据检查继续保留。服务端迁移与请求量记录见 [V0.3 服务端卡查](../docs/acceptance-v0.3-server-search.md)。原有手机、拖拽和交互检查见 [V0.2.4 操作简化](../docs/acceptance-v0.2.4-simple-playtest.md)与此前记录。

```text
npm test
python -m unittest discover -s tests -p "test_catalog_*.py" -v
```

数据刷新和清洗见 [scripts/README.md](scripts/README.md)。冻结数据的来源、覆盖、译文状态与修复审计见 `web/data/manifest.json`、`coverage-report.md` 和 `DATA-LICENSE.md`。

中文非空覆盖率、翻译正确率、人工校对率分别记录。上游 AI 译文和项目 AI 修订均明确标注，尚未宣称全库人工审核。全部语言印刷版本、特殊统帅组合的完整自动校验仍有范围限制。真实移动浏览器兼容和人工译文样本验收需继续完成。

测试进度与卡组备份分开，当前 JSON 卡组备份不包含测试现场。存档保留历史字段以兼容既有格式，界面不提供撤销／重做。单场最多 1000 张正式牌、含衍生物共 1200 张。测试现场只保存在当前浏览器。
