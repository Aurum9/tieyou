# 客户端统计与兼容门槛

页面版本 0.6.6 起，请求携带 `X-Tieyou-Protocol: 1`。支持自动更新页面的 Android 0.2.2 无需再安装 APK，收到新的页面资源后即可开始报告版本和统计。浏览器也携带协议标记，首次刷新即可切换。

## 统计口径

- APK 下载记录为服务器完成的 GET 200 响应，不记录 HEAD、已知未完成的响应或服务器回环自检，不代表唯一下载人数或安装完成。
- 首次启动统计为允许匿名统计且成功联网的随机标识数，不会补算历史安装、始终离线或关闭统计的用户。清空数据、重新安装可能重复计数。
- 版本分布按最近报告的 App 版本统计，可查看每日、近 7 天、近 30 天活跃情况。
- 每设备每天上报一次；同日覆盖升级允许再报告一次，服务器仍去重为同一设备。
- 标识为本地随机 UUID，服务器仅保存其 SHA-256，不保存原始标识、IP、账号、硬件标识或牌表。账号窗口可关闭匿名使用统计。
- 明细活跃日保留 90 天；下载、协议流量为每日汇总。统计单独使用 client-usage.sqlite，不与卡库数据库争用写锁。
- 报表仅在服务器命令行查看，无公开统计接口：`EDH_STATE_DIR=/home/ubuntu/.local/edh-atlas/state node scripts/client-usage-report.mjs`。

## 旧客户端联网限制

旧版 0.2.0 内置页面无法添加协议标记。服务端启用门槛后，其卡查接口返回 426，并提供“网页刷新 / App 下载新版覆盖安装”的文字提示。旧版现有页面会显示服务端错误文字，无法远程给它添加可点击的原生升级弹窗。

登录、套牌同步、备份和导出入口保持可用；离线已有功能也不受门槛控制。服务端限制可以要求用户升级后继续联网查牌，不能替用户安装 APK。

配置位于 state/client-policy.json。缺少配置或配置无效时保持兼容。先发布新网页和页面更新包，留出刷新与更新的时间，再根据无协议流量决定启用日期。旧浏览器页面、爬虫同样可能没有协议标记，不能把这些流量当作旧 App 安装数。

待确认后可写入以下配置（示例时间需替换为实际通知日期）：

```json
{"minimumProtocol":1,"enforce":true,"enforceAt":"2026-12-01T00:00:00+08:00"}
```

两秒内生效，无需重启。关闭时将 enforce 设为 false。默认不启用限制。

启用后，发布脚本、健康检查及维护工具调用卡查接口时，也应携带 `X-Tieyou-Protocol: 1`。更新清单、页面文件、登录及套牌同步接口不受此门槛限制。
